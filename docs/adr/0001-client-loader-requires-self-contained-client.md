# ADR 0001: клиентская половина плагина обязана быть самодостаточной

- Статус: принято (2026-09-10)
- Контекст: dsh-subscriptions, ядро DeepSeek Harness (dsh-client-hmr / client-modules loader)

## Контекст

Клиентский загрузчик DSH бандлит плагинные client-записи и не резолвит
относительные ESM-импорты внутри `lib/client.js`. Попытка декомпозиции
клиентской половины на модули (issue #266, коммит 36c5e9b, ре-ленд 73ed5b4)
дважды приводила к падению загрузки клиентского бандла («Failed to load
plugins» для всех записей ядра). Изначально сбой был ошибочно приписан
нашему пакету; последующая диагностика (issue #277) показала, что ядро само
падало на своём бандле, но контрольный эксперимент на починенном контуре
подтвердил: сплит клиента ломает загрузку и без участия чужих плагинов,
монолит работает.

## Решение

`lib/client.js` остаётся единым самодостаточным файлом: loader entry,
словари, компоненты и регистраторы живут в нём. Разрешено выносить только
то, что НЕ попадает в клиентский бандл (серверные модули, тесты, документация).
Лимит 800 строк из чеклиста code review для `lib/client.js` отменяется
контрактом загрузчика (superseded).

## Последствия

- Размер client.js будет расти с добавлением вендоров; компенсация —
  консолидация стилей в `lib/ui-styles.js` и компактный код, а не сплит.
- Если ядро добавит поддержку бандлинга относительных импортов (или официальный
  механизм модулей для клиентских записей), решение пересматривается: наработки
  сплита сохранены в истории (36c5e9b, 73ed5b4).

## Как проверить

Установить кандидат на изолированный test server и открыть Settings → Plugins:
появление «Failed to load plugins» при монолитном client.js означает внешнюю
причину (см. #277); при сплитнутом — подтверждает настоящее ограничение.
